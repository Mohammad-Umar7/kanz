# Kanz API (v1)

JSON over HTTP. The backend holds every key; the app never calls Gemini or Google Maps Platform directly.

- Source of truth for shapes: `backend/app/schemas/*.py` (Pydantic).
- Example bodies for every endpoint: `contracts/fixtures/*.json` (generated by `backend/scripts/make_fixtures.py`).
- Dart mirror: `app/lib/core/data/models/`, tested against the same fixtures.
- Shared vocabularies (materials, tools, state tags, hazards, facility types, cities): `contracts/vocab.json`.

## Conventions

| Topic | Rule |
| --- | --- |
| Base URL | `http://<host>:8000` in development (emulator: `http://10.0.2.2:8000`), HTTPS in production |
| Language | `lang` is `en` or `ar`. Free text in responses is in that language; enum values and JSON keys stay English |
| Request id | Every response has an `X-Request-ID` header; error bodies repeat it |
| Timings | Every AI response has `timings_ms` (stage -> milliseconds) |
| Images | Returned as paths such as `/static/generated/<image_id>/<name>.jpg`; join with the base URL. Generated images are cached by key |
| Rate limit | Per client IP, `RATE_LIMIT_PER_MINUTE` (default 90) across `/v1`; `429` with code `rate_limited` |
| Errors | Non-2xx bodies are `ErrorResponse` (see below) |

### Error codes

| HTTP | `error.code` | Retryable | When |
| --- | --- | --- | --- |
| 400 | `bad_request` | no | Missing/invalid fields |
| 400 | `image_invalid` | no | Not a decodable image |
| 413 | `image_too_large` | no | Upload over `MAX_UPLOAD_MB` |
| 404 | `not_found` | no | Unknown `image_id` / `tutorial_id` |
| 422 | `bad_request` | no | Validation error (message names the field) |
| 429 | `rate_limited` | yes | Too many requests |
| 502 | `ai_invalid_output` | yes | Model output failed validation twice (after the repair round) |
| 503 | `ai_unavailable` | yes | Gemini overloaded / unreachable after retries and fallbacks |
| 503 | `ai_quota_exhausted` | no | Model quota is 0 or used up (e.g. image models on a free-tier key) |
| 503 | `places_unavailable` | yes | Places and Overpass both failed |
| 504 | `ai_timeout` | yes | Stage exceeded its timeout |
| 500 | `internal` | no | Anything else |

```json
{"error": {"code": "ai_unavailable", "message": "The AI service is busy right now. Please try again in a moment.", "retryable": true, "request_id": "req_5f3c2a1b"}}
```

## The core flow

```
app                                   backend
 | POST /v1/analyze (photo)  ------->  Material Analyst -> Safety flags           (< 6 s)
 | POST /v1/recommend        ------->  Safety Router -> Retriever -> Upcycle || Recycle || Donate || Drop-off Locator (< 8 s)
 |   POST /v1/facilities     ------->  Places (New) / Overpass / curated          (parallel with images)
 |   POST /v1/images/after x3 ------>  Image Director -> Gemini image edit        (async, skeletons first)
 | POST /v1/tutorial (idea)  ------->  Retriever -> Tutorial Writer               (< 10 s)
 |   POST /v1/images/step 1..n ----->  step chain: each step edits the previous step's image
```

The app's pipeline timeline shows one stage per call above: Identifying materials (`analyze`), Checking safety and finding ideas (`recommend`), Locating drop-off points (`facilities`), Rendering makeovers (`images/after`).

## Endpoints

### `GET /health`

Warm-up and status. `HealthResponse`: `status`, `app_name`, `version`, `models`, `ai_configured`, `knowledge_docs`, `rag_ready`, `places_google`, `places_osm`, `uptime_s`. Fixture: `health.json`.

### `POST /v1/analyze`

`multipart/form-data`:

| Field | Type | Notes |
| --- | --- | --- |
| `image` | file (JPEG/PNG/WebP) | Optional if `text` is given. The app sends ~1600 px long edge, JPEG q85 |
| `text` | string | Optional if `image` is given. "a pile of old denim jeans" |
| `lang` | `en` \| `ar` | Default `en` |

Response `AnalyzeResponse`: `image_id` (`img_...` for photos, `txt_...` for text), `image_url`, `image_width`, `image_height`, `analysis`, `lang`, `timings_ms`.

`analysis.items[]` carries, for every item or raw material: `name`, `category`, `material`, `resin_code`, `is_raw_material`, `quantity {value, unit, is_estimate, display}`, `quality {score 1-5, label, notes}`, `state[]`, `recyclability {status yes|conditional|no, stream, prep_steps, reason}`, `reuse {level, note}`, `hazards[]`, `confidence`, `bbox {x, y, w, h}` (0..1, top-left origin, may be null).

`analysis.photo` is `{usable, issue, retake_tip}`. When `usable` is false the app asks for a retake and shows `retake_tip`.

Fixtures: `analyze_glass_jar.json`, `analyze_glass_jar_ar.json`, `analyze_battery.json`, `analyze_tshirt.json`, `analyze_unclear.json`, `analyze_text_caps.json`.

### `POST /v1/recommend`

Body `RecommendRequest`: `image_id`, `analysis` (possibly user-corrected; corrected items have `user_corrected: true`), `profile {skill, tools[], lang}`, `focus_item_id?`.

Response `RecommendResponse`:

- `routing {mode: diy|mixed|disposal_only, hazardous_item_ids, reason}` from the Safety Router.
- `upcycle[]`: exactly 3 `UpcycleIdea` unless `disposal_only`. Each: `id`, `title`, `pitch`, `difficulty`, `time_minutes`, `tools_needed`, `tools_have`, `tools_missing`, `uses_item_ids`, `extra_materials`, `after_visual` (English, for images), `safety_note`, `sources[]`.
- `recycle {instructions[] {item_id, status, stream, prep_steps, dos, donts, note}, sources}`.
- `donate {available, summary, options[] {item_id, suitable, reason, where, prep_steps}}`.
- `disposal[]` for hazardous items: `{item_id, hazard, headline, steps, never}`.
- `facility_categories[]`: `{key, label, facility_types, material_categories, item_ids}` to pass to `/v1/facilities`.

Fixtures: `recommend_request_glass_jar.json`, `recommend_glass_jar.json`, `recommend_glass_jar_ar.json`, `recommend_battery.json`, `recommend_tshirt.json`.

### `POST /v1/tutorial`

Body `TutorialRequest`: `image_id`, `idea` (an `UpcycleIdea` from `/recommend`), `items` (the scan items it uses), `profile`.

Response `TutorialResponse { tutorial, timings_ms }`. `Tutorial`: `tutorial_id` (deterministic for image, idea, skill, tools, lang), `idea_id`, `image_id`, `title`, `adapted_note`, `skill`, `total_minutes`, `materials[] {name, quantity, from_scan, item_id}`, `tools[] {tool_id, have, alternative}`, `safety[]`, `steps[] (5-8) {number, title, instruction, tip, warning, duration_minutes, image_prompt}`, `finishing[]`, `care[]`, `sources[]`, `lang`.

Changing `profile.skill` or `profile.tools` yields a new `tutorial_id` and a re-adapted tutorial. When `STEP_IMAGES_AUTOSTART` is on, the backend starts generating step images in the background as soon as the tutorial is created.

Fixtures: `tutorial_request_jar_lantern.json`, `tutorial_jar_lantern.json`, `tutorial_jar_lantern_ar.json`.

### `POST /v1/images/after`

Body `{image_id, idea, regenerate?}`. Edits the user's photo into the finished project (keeps the object's identity, lighting and camera angle; 4:3). Response `ImageResponse {url, width, height, kind: "after", key, cached, timings_ms}`. Fixture: `image_after.json`.

### `POST /v1/images/step`

Body `{image_id, tutorial_id, step, regenerate?}`. Step 1 edits the original photo; step N edits step N-1's image (original photo as an extra reference); the last step also references the idea's after image. Missing earlier steps are generated first. Cached by `(image_id, idea, step, skill)`. Response `ImageResponse` with `kind: "step"`, `step`, `skill`. Fixture: `image_step.json`.

### `POST /v1/images/bin`

Body `{image_id, item, prep_steps, regenerate?}`. The item shown correctly prepared for its bin (rinsed, cap off, flattened). Response `ImageResponse` with `kind: "bin"`.

### `POST /v1/facilities`

Body `FacilitiesRequest`: `categories[]` (keys), `lat`+`lng` or `city` (`abu_dhabi`, `al_ain`, `dubai`, `sharjah`, `ajman`, `umm_al_quwain`, `ras_al_khaimah`, `fujairah`), `radius_m` (default 15000), `limit` (default 20), `lang`.

Response `FacilitiesResponse`: `places[]` sorted nearest first (`id`, `name`, `address`, `lat`, `lng`, `distance_m`, `open_now`, `phone`, `website`, `maps_url`, `facility_types`, `category_keys`, `accepted_materials`, `accepted_note`, `rating`, `source: google|osm|curated`), `center`, `center_label`, `sources_used`, `notice`. Place data comes only from Google Places API (New), OpenStreetMap and the team's verified curated file; nothing is generated. Fixture: `facilities_glass.json` (fixture places are labelled "Fixture").

### `GET /v1/facilities/categories?lang=en`

The category catalog for the Drop-off tab's filter chips. `FacilityCategoriesResponse {categories[], lang}`. Fixture: `facility_categories.json`.

### `POST /v1/swaps`

Body `SwapsRequest`: `materials[]` (chip ids and/or free text), `history?` (`{period_days, counts {material: n}, top_items[], top_item_counts[]}` computed on the device), `lang`.

Response `SwapsResponse`: `swaps[] {id, from_item, to_item, why, tip, effort, cost, category, impact_note, matched_input, from_history, sources}`, `history_insight`, `lang`, `timings_ms`. Fixtures: `swaps_request.json`, `swaps_plastic.json`.
